# Artifact Protocol - Shared Schema

This directory contains the **single source of truth** for the Artifact Protocol used across plugin, backend, and frontend layers of TaskingAI.

## Schema Version

Current version: **v1.0.0**

| File | Description |
|------|-------------|
| [`v1.0.json`](./v1.0.json) | JSON Schema definition (the canonical source) |
| [`generate_artifact_types.py`](./generate_artifact_types.py) | Code generator for all layers |
| [`artifact_schema_validator.py`](./artifact_schema_validator.py) | Runtime schema validator (copied to plugin/backend) |

## Artifact Types

Only these 5 types are supported across all layers:

| Type | MIME Type | Description |
|------|-----------|-------------|
| `text` | `text/plain`, `text/markdown`, etc. | Text content |
| `image` | `image/png`, `image/jpeg`, etc. | Images |
| `file` | `application/pdf`, `application/zip`, etc. | Generic files |
| `json` | `application/json` | Structured JSON data |
| `table` | `application/json` | Tabular data (JSON array format) |

## Standard Fields

All artifacts must conform to this 8-field schema:

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| `type` | enum | ✅ | One of: `text`, `image`, `file`, `json`, `table` |
| `mime_type` | string | ✅ | Format: `type/subtype`, lowercase, 1-128 chars |
| `title` | string \| null | ❌ | Max 128 chars (truncated if longer) |
| `content` | string \| null | ❌ | Max 4096 chars (truncated if longer) |
| `preview_url` | string \| null | ❌ | Valid URI format |
| `download_url` | string \| null | ❌ | Valid URI format |
| `size` | integer \| null | ❌ | >= 0 (bytes) |
| `metadata` | object | ✅ | Default: `{}` |

## How to Make Changes

**DO NOT edit the generated files directly!** Follow this process:

### Step 1: Update the JSON Schema

Edit `v1.0.json` (or create `v1.1.json` for breaking changes).

### Step 2: Regenerate All Layer Code

```bash
cd /path/to/TaskingAI
python contracts/artifact/generate_artifact_types.py
```

This will regenerate:
- `backend/app/models/tool/artifact.py`
- `plugin/app/models/artifact.py`
- `frontend/src/types/artifact.ts`

### Step 3: Copy Runtime Validator

The validator is already copied to:
- `backend/app/utils/artifact_schema_validator.py`
- `plugin/app/utils/artifact_schema_validator.py`

If you update `artifact_schema_validator.py` in this directory, re-copy it:

```bash
cp contracts/artifact/artifact_schema_validator.py backend/app/utils/
cp contracts/artifact/artifact_schema_validator.py plugin/app/utils/
```

## Versioning Strategy

- **Patch version** (1.0.x): Backward-compatible changes (new optional fields, relaxed constraints)
- **Minor version** (1.x.0): Backward-compatible additions (new types, new required fields with defaults)
- **Major version** (x.0.0): Breaking changes (remove types, add required fields without defaults)

For new major/minor versions, create a new directory (e.g., `contracts/artifact/v1.1/`) and update the generator accordingly.

## Runtime Validation

Both plugin and backend layers validate artifacts against the shared JSON Schema at runtime:

```python
from app.utils.artifact_schema_validator import validate_artifact, validate_artifact_list

# Validate a single artifact
is_valid, errors = validate_artifact(artifact_dict)

# Validate a list
is_valid, errors = validate_artifact_list(artifact_list)
```

Validation failures are logged as warnings (not exceptions) to avoid breaking production flows.
